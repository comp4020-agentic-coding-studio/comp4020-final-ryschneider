# CLAUDE.md

Rules for the agent working on Margins. Each one exists because it came up in this project. If a rule here isn't one I'd enforce, it shouldn't be here.

## Platform beats the literal request

This repo deploys with Docker to Fly.io. If an instruction, script, or template assumes a different platform (GitHub Pages, serverless, a static host), do not force it through. Stop, say what doesn't fit, and propose the version that does. A flagged mismatch is a good outcome; a working-looking mismatch is not.

## Flag assumptions, don't pick silently

When a choice changes what the product does or looks like, state the assumption and the alternative before building on it. Examples: how finely heat is rendered along the text, how far a mark spreads, what a viewer counts as. If you would have to add a fixture or seed that causes a production side-effect to make something testable, flag that instead of adding it.

## Production code stays honest

No demo data, auto-seeded rooms, or test fixtures in production paths. Seeding is a separate script that a person runs on purpose. That script imports the real modules; it never carries a copy of the rule it is exercising.

## Commits and citations

One logical change per commit, with a message that says what and why. Cite a commit in PROCESS.md only after it exists, as a real link. Never write a placeholder for a commit that hasn't landed.

## Corrections that apply to a pattern

If I correct something that is likely to recur across the work, not just in one place, do two things: fix the instance, and propose the rule change that would prevent the pattern. Do not edit this file on your own. Show me the proposed rule and wait for my yes, because this file is the harness and I own it.

## Scope for this stage

Prefer the simplest thing that makes the shared text read correctly live. Single machine, in-process fan-out, SSE for push and POST for writes. Do not introduce a pub/sub layer, WebSockets, or accounts without asking.

## Read ARCHITECTURE.md first

ARCHITECTURE.md is the reference for the data model, the room engine's propagation/fade invariant (a note is visible iff it's still in the live map, nothing else), the SSE-over-WebSockets call, routes, and the seeding workflow (local and production, same script). Read it before touching src/lib/rooms.ts, the schema, routes, or Dockerfile/fly.toml. Update it in the same commit as any change that makes part of it stale — a doc that's silently drifted is worse than no doc.
